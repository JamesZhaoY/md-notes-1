# MD Notes

A Markdown notes web app that runs on **Cloudflare Workers + D1**, entirely within the free tier. No server required.

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/JamesZhaoY/md-notes)

> The button points to `github.com/JamesZhaoY/md-notes`. If you forked the project elsewhere, replace the repository URL in the link.

- Note list with full-text search on the left; edit / split / preview views on the right
- Autosave (800 ms debounce) while typing, `⌘/Ctrl + S` to save immediately
- GitHub-flavored Markdown: tables, task lists, code blocks, blockquotes; links open in a new tab
- Title is taken from the first line automatically; the list shows an excerpt and a relative time
- One-click export to `.md`; light / dark theme follows the system; drawer-style list on phones
- **Single user**: the login password comes from the `AUTH_PASSWORD` environment variable. There is no sign-up and no user table; the browser stores only a SHA-256 token of the password
- Zero-framework, zero-build frontend; `marked` and `DOMPurify` are self-hosted, no external CDN
- MIT licensed

## Deployment

Pick any one of the three routes. All of them stay within Cloudflare's free plan.

| Route | What you need | Best for |
| --- | --- | --- |
| **① Deploy button** | Cloudflare account + GitHub account | Fastest, about 3 minutes, just clicking |
| **② Dashboard (GUI)** | Cloudflare account + GitHub account | Nothing to install, see every step |
| **③ wrangler CLI** | Node.js 18+ on your machine | Developers who want to edit the code locally first |

### Route 1: Deploy button

Click **Deploy to Cloudflare** above → sign in to Cloudflare and authorize GitHub → on the setup page confirm the repository name, Worker name and D1 database name, and enter a value for `AUTH_PASSWORD` → **Create and deploy**.

Cloudflare copies the code into your GitHub account, creates the D1 database, deploys the Worker, and redeploys automatically on every future push. Details in the [dashboard guide, route A](./docs/deploy-dashboard.en.md#route-a-deploy-button-about-3-minutes).

### Route 2: Dashboard (GUI)

No command line; everything happens in the browser: put the code on GitHub → create a D1 database in the dashboard → paste the Database ID → import the repository to create the Worker → set the password.

Full step-by-step guide with exact button names and common errors: **[docs/deploy-dashboard.en.md](./docs/deploy-dashboard.en.md)**

### Route 3: Command line

Requires Node.js 18+.

```bash
# 1. Install dependencies (wrangler is a project dependency, no global install needed)
npm install

# 2. Log in to Cloudflare (opens a browser window)
npx wrangler login

# 3. Deploy. wrangler creates a D1 database named md-notes and writes its ID back into wrangler.toml
npm run deploy

# 4. Set the login password (required) — the AUTH_PASSWORD environment variable, 16+ random characters
npx wrangler secret put AUTH_PASSWORD
```

The deploy prints a URL like `https://md-notes.<your-subdomain>.workers.dev`. Open it and enter the password from step 4. The table is created on the first request; there is no migration to run.

To ship a change later, run `npm run deploy` again. Keep the `database_id` that step 3 wrote into `wrangler.toml` so later deploys don't have to look the database up.

### About the login password

This is a single-user app: **the only credential is the `AUTH_PASSWORD` environment variable**. There is no sign-up page and no user table; anyone who knows the password can read and write every note. When the variable is missing, every endpoint returns 503 and the page shows a setup hint instead of opening up.

Three equivalent ways to set it — pick one (don't combine two):

| Method | Command / location | When to use |
| --- | --- | --- |
| Secret (recommended) | `npx wrangler secret put AUTH_PASSWORD` | Encrypted, never enters the repository |
| Dashboard | Workers & Pages → md-notes → Settings → Variables and Secrets → Add, type **Secret** | Dashboard deployments, no wrangler installed |
| Plaintext variable | `[vars]` `AUTH_PASSWORD = "..."` in `wrangler.toml` | Private repository, convenience |

For local development put it in `.dev.vars` (see below).

### Custom domain (optional)

The `workers.dev` domain is unreliable in some regions. If your domain is on Cloudflare:
Dashboard → Workers & Pages → `md-notes` → Settings → Domains & Routes → Add → Custom Domain, enter a subdomain such as `notes.example.com`. The certificate is issued automatically.

## API

Every endpoint except `/api/auth/*` requires the header `Authorization: Bearer <token>`, where the token is returned by the login endpoint (it is the hex SHA-256 of the password). When `AUTH_PASSWORD` is not configured, everything except `status` returns 503.

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/auth/status` | `{ configured: boolean }` — whether the server has a password |
| POST | `/api/auth/login` | `{ password }` → `{ token }` |
| GET | `/api/notes?q=keyword` | List (newest first, up to 500); `q` optionally searches title and body |
| POST | `/api/notes` | `{ content }` → the new note |
| GET | `/api/notes/:id` | Full note |
| PUT | `/api/notes/:id` | `{ content }` → `{ id, title, updated_at }` |
| DELETE | `/api/notes/:id` | Delete, returns 204 |

With the API you can script bulk imports, e.g. every `.md` file in a directory:

```bash
TOKEN=$(curl -s -X POST https://your-domain/api/auth/login \
  -H 'content-type: application/json' -d '{"password":"your-password"}' | jq -r .token)
for f in *.md; do
  jq -Rs '{content: .}' "$f" | curl -s -X POST https://your-domain/api/notes \
    -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' -d @-
done
```

## FAQ

**The page says the server has no password configured.**
The `AUTH_PASSWORD` environment variable is missing — see "About the login password". Locally, it means `.dev.vars` is missing.

**Forgot the password / want to change it?**
Run `npx wrangler secret put AUTH_PASSWORD` again (or edit the Secret in the dashboard and click Deploy). Tokens on every signed-in device become invalid immediately; enter the new password to continue.

**Can I add more users?**
No — it is single-user by design, with no sign-up or user management. To share with someone, have them deploy their own copy; it costs nothing.

**Can the password be brute-forced?**
There is no login rate limiting, so security rests on password strength — use 16+ random characters. For stronger protection put Cloudflare Access (Zero Trust, free for up to 50 users) in front of the domain; it supports email one-time codes, GitHub and other identity providers.

**What if two devices edit the same note at once?**
Last write wins. This is a personal notes tool, not a collaborative editor.

**Code highlighting / math?**
Include highlight.js or KaTeX in `public/index.html` and configure the renderer in `marked.use({...})` inside `public/app.js`. Nothing else needs to change.

**Upgrading marked / DOMPurify?**
`npm update marked dompurify && npm run vendor`, then redeploy.

## How it works

- **Static Assets**: the `[assets]` block in `wrangler.toml` lets Cloudflare serve `public/` directly; static requests never hit the Worker and aren't billed. Only `/api/*` reaches `src/index.js`.
- **Automatic table creation**: the Worker runs `CREATE TABLE IF NOT EXISTS` on the first request handled by each isolate, so there is no migration step.
- **Automatic D1 provisioning**: with `database_id` left empty, wrangler looks up or creates the database by `database_name`; CLI deployments don't need `d1 create`.
- **Authentication**: the only credential is the `AUTH_PASSWORD` environment variable. The server compares with `crypto.subtle.timingSafeEqual` to avoid timing side channels; the browser stores only the SHA-256 token.
- **XSS protection**: the preview passes `marked`'s output through `DOMPurify`; everything else is written with `textContent`.
- **Search**: SQLite `LIKE` with `%`, `_` and `\` escaped; CJK text matches by substring.
